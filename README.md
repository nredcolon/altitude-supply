# 螺蛳湾 · 海外供货平台

可运行的首版业务验证应用，依据《产品二：海外供货平台——产品与业务设计》及本次对话确认的收费边界开发。

**产品原则：供货平台对商户免费。商品与供货能力独立审核；无需购买出海联盟会员，不收取商户入驻费、会员费或成交佣金。实际运输、包装等费用在交易条件中另行约定。**

## 当前版本

2026-10-13：已完成本地开发与验证，尚未在线部署。私有站点已登记；上传源码和发布需取得明确授权后继续。最终构建、TypeScript 检查、14 项核心业务测试及 API 冒烟检查均通过；已在浏览器验证商品提交与审核、报价确认转订单，以及桌面和 390px 手机布局。界面截图见 `outputs/dashboard.png`。

这是仅供所有者访问的开发验证版。通过 ChatGPT 登录后，每个账号有独立的 D1 工作空间；工作空间内使用明确标注的示例商户、渠道、订单和款项。顶部“体验身份”用于同一所有者模拟运营、供货商和海外采购方。

该身份切换属于演示功能，并非正式的商户登录授权。不能将当前站点直接开放为真实多人交易系统。

## 已实现

- 运营、供货商、采购方三个操作视角，以及相应的服务端数据投影与操作校验。
- 商户登记、准入审核；商品提交、编辑、审核和待补资料反馈。
- 采购需求、包含多个商品和供货商的正式报价、主体与交付/结算条款、报价有效期。
- 报价转订单时检查商品状态、价格、规格、起订量和库存；生成订单并预留库存，禁止重复转单。
- 分商户确认供货；核验足额收款后启动供货；分商户登记国内交货。
- 到仓验货、差异登记、异常处理和复验。未解决异常与数量不一致会阻断验货通过。
- 关务放行和税务资料归档分别管理；验货、收款和通关条件满足后才能登记发运。
- 承运商、运单、预计到达、海外签收，以及独立订单/物流/关务/税务/资金状态。
- 依据签收结果生成商户应结金额，支持分批登记付款、防止超额付款及重复凭证，平台费固定为零。
- 异常及售后、服务请求、操作记录、订单 CSV 导出、桌面及手机适配。
- 所有业务变化通过单次数据库版本比较写入；并发或陈旧页面收到冲突提示，不覆盖新记录。

## 技术结构

- Vinext / React / TypeScript，Cloudflare Worker 路由。
- D1 持久化，Drizzle 管理数据库迁移。
- `app/supply-app.tsx`：三个角色的界面和业务表单。
- `app/api/workspace/route.ts`：身份检查、私有工作空间、命令接口、版本冲突控制。
- `lib/supply/domain.ts`：纯业务状态转换、校验和数据可见范围。
- `lib/supply/types.ts`：业务对象类型。
- `lib/supply/seed.ts`：有明确示例标识且关联一致的样本数据。
- `tests/domain.test.mjs`：14 项核心规则测试，包括多商户订单到结算关闭的完整流程。
- `tests/api-smoke.mjs`：本地数据库、身份、冲突和数据隔离验证。

首版将单个工作空间的关联业务对象作为一个带版本号的 JSON 聚合保存在 D1，以保证每次业务变更和操作记录原子提交。它适合小规模流程验证，不是大规模订单系统的最终数据库设计。正式多组织版本应拆分业务表、引入组织成员关系、按对象授权、独立审计、查询索引和分页。

## 本地运行

需要 Node.js 22.13 或以上版本及 npm。Sites 自带的开发模式提供本机模拟登录，正式部署使用平台身份。

```sh
npm run dev -- --port 5178 --hostname 127.0.0.1
npm run check
npm test
npm run test:api
```

`test:api` 在正在运行的本地服务中新增一条明确标注的测试服务请求，不向外部系统发送消息。测试地址为本机 5178 端口。

首次预览前，生成构建配置并应用迁移：

```sh
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_tough_shadow_king.sql
```

已应用的迁移不要重复执行。托管发布由 Sites 工作流同步源码、构建和应用数据库迁移。

## 业务验证路径

1. 切换供货商，提交一件商品。
2. 切换运营，审核商品和商户。
3. 采购方发布需求，运营填写报价、实际交易主体及完整条件。
4. 采购方确认报价，系统建立供货订单；供货商分别确认。
5. 运营登记收款核验，启动供货；商户登记到仓交货。
6. 运营验货；有差异时先登记并解决异常，再复验。
7. 登记通关放行、承运商和运单，采购方确认签收。
8. 按供货商核对货款，登记分批付款；税务归档及全部结清后关闭订单。

## 真实试运营前仍需完成

- 明确实际采购、出口、进口、收付款和服务主体，确认合同、责任边界和具体业务模式。
- 引入组织、正式成员邀请和服务端权限；取消演示身份切换，增加运营与财务的复核职责分离。
- 接入或建立真实材料审核、文件上传与访问权限、商品照片、凭证保管和保留期限。
- 按已确认的合作协议接入物流、支付、关务等接口；目前仅人工登记凭证编号和核实说明，不执行银行转账或物流下单，也不核验凭证真伪。
- 目前界面以中文为主。泰国渠道需泰语运营辅助，正式泰语/英语版本尚未实现。
- 首版仅支持人民币报价和整单足额收款启动供货；信用账期、多币种、换汇、费用分摊、退款、取消、延期、换货及商品替代需要独立规则和测试。
- 完善真实预算、人员排期、服务容量、告警、备份恢复、审计与真实小额试单。

交付/付款界面记录与真实外部交易相互独立；示例数据不证明真实渠道、订单、放行或资金到账。
