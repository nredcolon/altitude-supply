# 山海供双入口统一后台验证

日期：2026年10月15日。软件版本：0.2.0-alpha.4。本轮按“两个登录地址、一套后台、角色与数据权限分开”调整 M1，不包含生产上线。

## 入口与角色

| 使用者 | 登录地址 | 工作台 | 权限 |
|---|---|---|---|
| 商户 | `/merchant/login` | `/merchant` | 自家商户资料、供货条件、操作记录和可关联的标准商品 |
| 运营 | `/operations/login` | `/operations` | 平台货盘、商户与商品审核、供货维护、商户账号认领 |
| 平台管理员 | `/operations/login` | `/operations` | 运营功能，以及运营成员邀请、核实、停用和恢复 |

两类入口共用账号认证、`CatalogApp`、业务服务和数据库。匿名访问工作台进入对应登录页；已授权账号走错工作台地址时由服务端引导到自身角色入口。登录地址不赋予角色；API 根据真实账号校验操作、数据归属和平台范围。

普通账号创建空间的 HTTP 操作已关闭。页面移除“建立运营空间”“加入其他空间”及空间切换。商户申请或认领平台档案，运营由平台管理员邀请开通。

## 现有数据与初始化

只有一份历史货盘时直接沿用。存在多份时，由服务器环境变量 `SHANHAI_WORKSPACE_ID` 明确选择；未选择或配置错误时关闭业务访问，不自动挑选、合并或删除。货盘读写、入驻码、专属邀请和图片接口均遵守相同的平台边界。浏览器传入其他 workspaceId 不能切换平台。

新空数据库先执行已有迁移，再由部署管理员使用本地 `platform:setup` 脚本初始化。初始化 SQL 只在货盘表为空时插入，重复执行不覆盖账号及业务资料。管理员用户 ID 必须取自可信登录系统。本轮未重新初始化现有本地货盘。

## 验证结果

| 检查 | 结果 |
|---|---|
| TypeScript 类型检查 | 通过 |
| 业务及 SQLite 接口测试 | 31 项通过；新增平台初始化、角色会话、错误入口拒绝及历史空间隔离验证 |
| 生产构建 | 通过；两个登录页、两个工作台、认领页及 API 均构建成功；保留框架关于首页静态分类的提示 |
| 本地登录页面 | 两个地址均返回 HTTP 200，包含对应登录内容，不显示运营空间注册 |
| 匿名及角色跳转 | 匿名工作台请求重定向至对应登录页；本地运营账号访问商户工作台重定向至运营工作台 |
| API 权限 | 错误角色入口返回403，普通账号和管理员均不能通过公共 API 创建空间；商户不能自我审核或提权 |
| 原业务回归 | 本地 D1 持久化、R2 图片、商品与供货维护、认领邀请生成及撤销通过 |
| 桌面、手机及多账号登录交互 | 未完成目视验收；多账号业务通过 SQLite 服务测试覆盖，本地身份固定为单一开发账号。此前浏览器控制入口受安全策略限制，本轮未绕过限制 |

本地接口验证仅新增明确标注的示例商户、商品、报价及邀请，结束后暂停测试报价并撤销测试邀请。未向真实商户发送邀请或修改原有供货条件。
