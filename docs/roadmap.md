# 开发路线图

供货平台对商户免费。商户提前维护标准商品及有效供货条件，系统根据采购需求匹配供应商；不建设逐单询价和商户回复流程。

## M1 商户与标准货盘

状态：已实现，进行本地验收。

- [x] 独立项目、版本控制、开发说明与 CI 配置。
- [x] 运营建立空间、商户邀请码入驻及服务端账号隔离。
- [x] 经营资料、准入与暂停；运营代录商户。
- [x] 平台标准 SKU、同款身份约束及审核。
- [x] 同一 SKU 多商户关联、供货价和可供量维护。
- [x] 起订量、数量倍数、交期、地点、有效期和报价版本。
- [x] 首次关联审核、下架、过期及不足量提示。
- [x] 类型检查、核心业务及 SQLite 接口测试。
- [ ] 实际商户样本验证，确认品类 SKU 标准。
- [ ] GitHub 仓库绑定、远程 CI 及 PR 流程验证。

验收案例：两家商户以不同价格和可供量关联一个标准 SKU，商户只能维护自己的报价，运营可以同时查看；过期和暂停货源不显示为有效供给。

## M2 自动匹配组货

依赖：M1 样本中，同款关系及供货价格口径能够可靠核实。

- [ ] 采购需求录入，运营将原始描述映射为明确 SKU。
- [ ] 按规格、交期、交货地点、有效性过滤候选供货。
- [ ] 考虑起订量和包装倍数的多供应商数量组合。
- [ ] 在可行组合中比较成本；同成本减少供应商数量。
- [ ] 输出缺口、排除原因、成本与供货条件快照。
- [ ] 运营调整方案，重算并记录原因。
- [ ] 方案采纳时重新校验并原子预占数量，支持释放。

验收案例：客户要500件，甲400件、乙200件、丙有货但超交期；系统分配符合规则的500件。无可行组合时明确说明缺口。两笔采纳不重复占用同一可供量。

## M3 对外报价

- [ ] 将内部组货方案转为客户版报价，供货成本与售价分离。
- [ ] 费用边界、交货及付款条件、有效期和报价版本。
- [ ] PDF或打印导出，不泄露商户底价及内部备注。
- [ ] 客户反馈与确认对应具体版本，失效后重新核验。

M1至M3组成首版。物流、关务、支付、结算和海外客户自助端，在上述能力经过实际试用后另排版本。参考四周只是工作包安排；实际发布日期依据人员投入和标准化样本结果确定。
